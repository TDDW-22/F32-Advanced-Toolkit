# F32 手机运维通道

刷入一次新 smsapi 之后，设备上的所有操作都能在手机浏览器完成，不再需要电脑和 adb。

## 新增的三个端点（原 smsapi 全部接口不变）

| 端点 | 作用 |
|---|---|
| `POST /api/file?path=&token=&append=&exec=` | 把**原始请求体**写入设备文件；`exec=1` 同时 chmod 755 |
| `GET /api/file?path=&token=` | 读回文件内容（JSON，含 size） |
| `GET/POST /api/exec?token=&cmd=` | 执行 shell 命令，返回 `rc` 与输出（上限 8KB） |

安全约束：
- 必须带 `token`，值与 `smsfwd.conf` 里的 `api_key` 一致（没配 `api_key` 时退回用 `secret`，两者都没有则直接拒绝）
- 路径必须落在白名单：`/mnt/userdata/etc_rw/`、`/tmp/`、`/etc_ro/web/`、`/sbin/`、`/etc/`、`/vendor/`、`/data/`
- 路径含 `..` 一律拒绝；单次请求体上限 32KB（运维页会自动分片，单片 7KB）
- 仍然只监听内网，CORS 只回显内网 Origin

## 部署（唯一一次需要电脑）

设备插 USB，双击 `一键开启手机运维.bat`，它会：
1. 备份现有 `/sbin/smsapi` → `smsapi.bak_prephone`
2. 推送新 smsapi 并替换
3. 生成随机 token 写入 `api_key`，重启 smsapi
4. 推送运维页到 `/etc_ro/web/m.html`
5. 屏幕打出 token 和手机地址

## 之后在手机上

1. 手机连这台设备的 WiFi
2. 浏览器打开 `http://192.168.0.1/m.html`
3. 第一次填 token（存在浏览器本地，之后不用再填）
4. 页面三块功能：
   - **写文件**：选手机里的文件 → 填目标路径 → 上传（自动分片、可选追加、可设为可执行、可读回校验）
   - **执行命令**：输入框直接执行；也有「自检 / 启动服务 / 停止服务 / 查看状态 / 转发日志 / 写开机自启」快捷键
   - **服务状态**：smsapi 状态、进程列表、系统信息

## 文件清单

| 文件 | 说明 |
|---|---|
| `smsapi` | 已编译好的 ARM 静态二进制（含新端点），落到 `/sbin/smsapi` |
| `smsapi.c` | 完整源码，可直接替换刷机包里那份 |
| `m.html` | 手机运维页，落到 `/etc_ro/web/m.html` |
| `一键开启手机运维.bat` | 一次性部署脚本 |

## 实测记录（x86 同源码本地跑通）

- 无 token / 错 token → 403 `token 无效`
- 白名单外路径（如 `/root/x`）→ 400 `路径不在白名单或非法`
- 正常写入 44 字节 → `{"ok":true,"bytes":44}`，权限 755
- 读回内容一致；追加写入后 size 62，内容正确拼接
- `sh /path/script.sh` → `rc=0`，输出正确
- 不存在命令 → `rc=127`

> 期间修掉一个 bug：主进程把 `SIGCHLD` 设成了 `SIG_IGN`，导致 `pclose` 拿不到退出码（恒为 -1）。已在 exec 路径临时恢复 `SIG_DFL` 再还原。

## 注意

- 新 smsapi 仍会写日志到 `/mnt/userdata/etc_rw/smsapi.log`，exec 的每条命令也会记一行，便于回溯。
- token 等于设备 shell 权限，别外传；泄露了用 `/api/save` 改 `api_key` 即可作废。
- 刷机包里的 `短信转发组件\smsapi.c` 建议同步成这份，重刷后不用再跑一次部署。
