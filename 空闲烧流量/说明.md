# 空闲烧流量组件 burnctl（C 守护，netlink 事件驱动）

## 逻辑：内核事件推送，不轮询

设备 busybox 裁掉了 curl/iw/hostapd_cli，hostapd 控制口也不响应，
因此本版改用 **NETLINK_ROUTE 的邻居组播（RTMGRP_NEIGH）**：
内核在局域网终端接入/失联时主动推送，守护纯阻塞等待，没有定时器。

```
netlink 邻居事件
 ├─ NEWNEIGH（192.168.0.0/24，非网关，状态非 INCOMPLETE/FAILED）
 │     → 判定终端接入，立刻杀掉烧流工作进程，带宽让出去
 └─ DELNEIGH / 状态变 INCOMPLETE/FAILED
       → 从在线表移除；表空后核对「网页手动 ICCID == 当前 ICCID」
            ├─ 完全一致 → 拉起烧流工作进程
            └─ 未填写 / 不一致 / 读不到 → 不启动，并停掉旧 worker
```

启动时一次性读 `/proc/net/arp` 初始化在线表（只认 flags=0x2 的完整条目）。

## 授权卡：网页手动填写 ICCID，实时比对一致才烧

不再使用内置 ICCID / 号码 / IMSI 白名单，也不再读 `burn_target`。授权流程：

1. 打开「空闲烧流量」页，页面会显示设备当前读到的 ICCID；
2. 在输入框**手动填写**同一张卡的 ICCID（18~20 位十六进制，含 A-F 也可以）；
3. 点「校验并授权」，服务端把填写值与设备实时读取值逐字比对：
   - 完全一致 → 写入 `/tmp/burn_manual_iccid`，通知 burnctl 重新判定；
   - 不一致 / 读不到当前 ICCID → 拒绝，清空授权，并立即停掉正在烧的 worker；
4. 即使已授权，只要局域网有终端在线也会立刻停烧；终端全部离开后才开始；
5. 授权只存在 `/tmp`，设备重启后自动清空，必须重新填写。

读取通道：本固件 goform 的 `ziccid` / `msisdn` 恒为空，实际走
`at_server` 的 9090 端口执行 `AT+ZICCID?`；ICCID 允许 BCD 十六进制串（含 A-F）。
调试可跑 `burnctl probe` 看当前 ICCID，`burnctl check` 看授权与放行结果。

三重保险，任何一环不满足都不烧：
1. 启动/事件触发烧流前先核对“手动 ICCID == 当前 ICCID”，不通过不启动；
2. 烧流子进程**每轮下载前复核一次**，发现换卡或授权被清空立即自行退出；
3. 守护收到授权更新后重新判定；授权为空/不一致时主动停掉旧 worker。

网页接口由 `smsapi` 提供（8080 端口）：

```
GET  /api/burn                 # 当前 ICCID、手动授权、是否匹配、烧流状态
POST /api/burn  iccid=...      # 校验并授权；不一致返回 409
POST /api/burn  action=stop    # 停止并清除手动授权
```

## 烧流动作

工作进程不依赖本机任何工具，裸 TCP 直连公网大文件循环拉取：
主源 `speed.cloudflare.com /__down?bytes=10000000`，每轮最多读 8MB 断开重连，
失败自动轮换备用源；单轮少于 100KB（404 页面等）视为失败。

## 首页查看烧了多少

网页「设备信息」详情页（首页点详情进入，显示 IMEI/ICCID/IMSI 那页）新增三行：

- **烧流量状态**：烧流中 / 空闲
- **累计烧流**：累计 MB（持久统计，重启不清零）+ 当前授权 ICCID
- **最近一轮**：上一轮下载 MB 数

首页配额卡片下也有一份同样的显示。页面改动后如看不到，按 Ctrl+F5 强制刷新清缓存。

数据由 burnctl 写 `/mnt/userdata/etc_rw/burn_info.txt`
（`累计字节|状态1/0|最近一轮字节|授权ICCID`），主 bat 把它软链到
`/etc_ro/web/js/burn_info.txt`，首页 JS 每 2 秒刷新一次。

## 编译（改源码后）

```sh
zig cc -target arm-linux-musleabi -mcpu=arm1136j_s -mfloat-abi=soft -O2 -static -s -o burnctl burnctl.c
```

必须带 `-mcpu=arm1136j_s -mfloat-abi=soft`（软浮点、无硬件除法），
否则默认目标的 VFP 指令在设备上会 SIGILL。编译后可先在任意 ARM 设备跑
`burnctl check` 验证能执行。

## 手动命令（设备上）

```sh
/mnt/userdata/etc_rw/burnctl check    # 自检：在线终端、手动/当前 ICCID、是否允许、netlink
/mnt/userdata/etc_rw/burnctl probe    # 只打印当前 ICCID（网页接口做即时比对）
/mnt/userdata/etc_rw/burnctl reload   # 重新读取 /tmp/burn_manual_iccid 并判定
/mnt/userdata/etc_rw/burnctl fetch    # 逐个试烧流源，打印字节数
/mnt/userdata/etc_rw/burnctl start    # 后台启动守护
/mnt/userdata/etc_rw/burnctl stop     # 全停（守护+工作进程）
/mnt/userdata/etc_rw/burnctl status   # 状态
/mnt/userdata/etc_rw/burnctl run      # 前台运行，实时看日志
cat /mnt/userdata/etc_rw/burn.log
```

手动授权（设备命令行）：

```sh
echo -n 898600382226F0D50388 > /tmp/burn_manual_iccid
/mnt/userdata/etc_rw/burnctl reload
/mnt/userdata/etc_rw/burnctl check
rm -f /tmp/burn_manual_iccid
/mnt/userdata/etc_rw/burnctl reload
```

## 状态文件（/mnt/userdata/etc_rw/）

- `burn.state`：1=正在烧，0=空闲
- `burn.worker.pid`：烧流工作进程 pid
- `burn.pid`：守护进程 pid
- `burn_total`：累计烧流字节（持久，重启不清零）
- `burn_info.txt`：首页显示数据（累计|状态|最近一轮|授权ICCID）
- `/tmp/burn_manual_iccid`：网页手动授权 ICCID（重启清空，不持久化）
- `burn.log`：运行日志

## 自启

主刷机 bat 在 `/etc/rc` 追加：
`( sleep 15; /mnt/userdata/etc_rw/burnctl start ) &`
开机 15 秒后自动拉起；此时授权为空，不会烧，必须先在网页手动填写 ICCID。
